# Bug hunt — 26 October 2026

Hostile code review of every Netlify function, engine, API helper, app shell, organiser/player/board views, Stripe/Resend paths, reviewer route, and tenancy boundaries.

## Systemic issue

**Nearly every organiser-facing function trusts the client-supplied `organiser_id` without verifying the caller's auth token.** The `org-auth.js` function correctly verifies JWTs, but no other function calls it to check the caller. If you know an organiser's UUID (visible in client code, URLs, cookies), you can impersonate them.

The player-facing functions (`score-save`, `player-nominate`, `player-context`) correctly authenticate via `player_token`, so the scoring path itself is secure IF the tokens aren't leaked. The problem is that `event-players.js` and `org-players.js` leak them without auth.

`public/shared/app-shell.js` — not found in the repo (may be missing or renamed). No native shell audit possible.
